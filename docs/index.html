OmniPet ships the Admin Pet Studio, a schema-4 player vault with ordered active intent, explicit-currency slot purchases, audited recovery, incubation both in hand and on the ground, and visible pets that follow their owner and settle down when it stops. Feeding, bonding, temporary buffs, and multi-pet formations remain roadmap work.

01 / Staging boot

From verified JAR to a controlled server check.

Use the Gradle release artifact on staging, preserve old data, and verify only the features that currently ship.

  1. 01
    Place the artifact

    Copy OmniPet-3.0.0-SNAPSHOT.jar into plugins/.

  2. 02
    Start on staging

    Confirm the Studio-enabled log line or capture the first fail-closed error.

  3. 03
    Open shipped flows

    Use /pet, /pet slot, and permitted Studio/admin branches.

  4. 04
    Verify recovery

    Run /pet admin transactions 20; paste the opaque next cursor when provided, and never replay an ambiguous economy call.

Architecture boundary

Shipped is not the same as certified.

Pets render, follow, and behave; incubation, progression, skills, and release all run. What has not happened is live certification — no crash-injection, process-kill, real inventory-event, live performance, or vendor smoke matrix. Compile probes and unit tests are necessary and insufficient, and this site says which is which on every page.
