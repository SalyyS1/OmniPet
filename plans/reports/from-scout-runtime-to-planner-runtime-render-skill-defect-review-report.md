# Runtime / Render / Skill / Buff / Progression defect review (scout-runtime -> planner)

Read-only pass over `omnipet-paper/.../paper/{runtime,render,skill,buff,progression}`, `OptionalAdapterLoader`, `OmniPetPlugin` enable/disable, `paper-plugin.yml`, plus core `PetActivationService` (2026-09-03). No file modified, no gradle run. Report persisted by planner from the scout's inline message (scout had no Write tool).

## Summary
- Two P1s: MythicMobs kill-identity bridge binds against the wrong classloader and can never recover (all MythicMobs kills priced as vanilla); skill trigger listener fans a disk-backed queue task to every player on every sneak/sprint/jump/damage event because most handlers skip the `hasTrigger` gate.
- Recurring P2 theme: "quarantine" in every reflective bridge conflates a bad pet/skill/buff input with a broken vendor ABI, so one authoring typo disables the whole integration for all players until reload.
- Per-tick cost hotspots: 3 teleports per ModelEngine pet per tick, renderer reconstruction via reflection every tick while quarantined, un-deduped runtime failure warnings per pet per tick.
- Threading is sound (main-thread asserts, synchronized snapshots, queue worker for disk). No `catch (Throwable)` in scope; swallows are documented fallbacks except those listed.

## Upgrade opportunities
- One quarantine policy for all five reflective bridges (`ReflectiveModelEngineBindings`, `ReflectiveModelEngineAnimationBindings`, `ReflectiveMythicMobsSkillProvider`, `ReflectiveMythicLibBuffPort`, `ReflectiveMythicMobsIdentity`): bridge-broken (class/method missing, `LinkageError`) vs input-bad (per pet/skill/buff). Surface every `unavailableDetail()` through one `/pet admin diagnose` (extend the `OwnerBuffDiagnostics` pattern).
- Shared `RateLimitedWarnings` helper for the runtime failure sink, buff coordinator, renderer fallback reporter, skill reindex swallow.
- Cache reflective `Method`/`MethodHandle` at refresh epoch in every bridge; hot paths (`isMythicMob`, `castSkill`, ModelEngine `getModeledEntity`) should never call `getMethod`/`getMethods` per invocation.
- Pet entity registry (all carrier/plate/interaction/display UUIDs) shared by target resolver, interaction index, and future "is this entity a pet" checks.
- Same-world teleport moves pets instead of despawn/respawn.
- Paper API drift check: compiled against `paper-api 1.21-R0.1-SNAPSHOT`; `Attribute.GENERIC_*` and `Registry` lookups are the known break points on 1.21.3+. Decide the supported range and add it to `compileCompatibilityJava` or a CI matrix.
- Runtime failure -> self-heal: after N consecutive update failures for a handle, retire it and let activation respawn.
