## Verdict

No P1. Core idle-play math, ordering, steering extraction, main-thread guarantee, config round-trip, overload defaults, reconcile argument indices, and the `getMaxHealth()` hotfix all check out against source and javadoc. Two P2s are worth fixing before commit: the config loader accepts any `Particle` name including data-requiring ones (DUST, BLOCK, ITEM, ENTITY_EFFECT, ...) and the sink uses the no-data `spawnParticle` overload, so a legal-looking config value produces a caught exception plus a warning line every burst for every playing pet; and the CHANGELOG claims every player argument was renamed while one usage string and the published wiki still carry the old hints. Remaining items are wording and one missing reload warning.
