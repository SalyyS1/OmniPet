# Changelog

## Unreleased - OmniPet 3.0 development line

### Added

- Added **language packs** and a complete **Vietnamese translation**. Text previously resolved from exactly one `messages.yml` with no locale concept at all. `gui.locale` now selects a pack from `lang/`, layered so that `messages.yml` still wins over it and the built-in English still backs both — which matters because `messages.yml` is generated on first start and many servers already have one edited in place, so replacing it with a `lang/` directory would silently discard that work. A key missing from a pack falls through instead of failing, so a half-finished translation is usable rather than rejected. Bundled packs are copied out once and never overwritten, so an operator's corrections survive an upgrade. A test asserts the shipped Vietnamese pack covers every key **and keeps every placeholder** — a dropped `<amount>` is worse than an untranslated line, because the value silently vanishes from the rendered message instead of merely reading as English.

- Added **particle celebrations** for the handful of moments a player actually waited for: a hatch claimed, a slot unlocked, a pet summoned. The plugin previously had no particles, titles, or boss bars anywhere. Bursts go through `FeedbackService` like every other cue rather than being sprayed from click handlers, so they inherit the per-player rate limit and the `gui.feedback.enabled` master switch, and they use the **player-scoped** `spawnParticle` overload — a world-spawned burst is visible to everyone nearby, which on a repeatable click is a griefing vector rather than a celebration. A source-contract test now guards that for particles the way it already did for sounds. Deliberately not applied to repeatable actions such as cycling the vault sort, which would read as clutter rather than reward. An unknown particle name costs the burst alone, warns, and leaves the sound intact.

- Added operator-configurable **menu restyling**. A new optional `gui.menus:` section gives each menu a size, a filler pane, and per-button material and slot; roughly ninety `Material` literals and every inline slot index are now overridable. Buttons are keyed by **name** rather than slot, because several tiles pick their material from state — the hatch tile differs when ready, incubating, and idle — so "the hatch tile" can be restyled without enumerating its states. Every placement binds the click action and the item in one call, which is the invariant that stops a moved button becoming a drawn control that does nothing; a move onto an occupied slot or outside the menu is refused with a warning naming the key. The vault takes materials but not slots or size, since its pet rows occupy 0-44 and the pagination arithmetic is built on that shape.
- Added **placed-egg incubation**: an egg placed beside a heat source hatches where it stands, with a `TextDisplay` countdown above it. An egg definition controls its surroundings — an ordinary egg wants any one heat source, a fire-affinity egg can demand a full ring of eight lava, and an egg may refuse placement entirely. The requirement is re-checked every second, so removing the heat pauses the countdown, and an unloaded chunk pauses rather than accrues. A placed egg is its own durable record at `data/placed-eggs/*.yml`, deliberately **not** an escrow row: escrow proves a held item was paid for, while a placed egg is one the player still owns. Breaking consumes the record before returning the item, so a break/place cycle cannot duplicate it, and the egg returned is the snapshot taken at placement. Holograms are always derived from records and never persisted, so a crash or unload leaves nothing to clean up.
- Added operator-configurable **egg and consumable appearance**: `material`, `customModelData`, `glint`, `itemFlags`, and extra lore per item, so a resource pack can finally give them models. Read at mint time only — an egg's escrow fingerprint hashes the stack as it was minted, so a reload restyles the next item while eggs already held or mid-hatch keep the look their record describes. Lore is capped at 12 lines of 256 characters, because the durable snapshot rejects a stack over 8 KiB.
- Admin commands now accept an **online player name or a UUID**, and the trailing action UUID is optional and generated when omitted. Tab-complete suggests online names at a player argument. Previously every recovery command demanded a raw UUID copied out of a YAML file, plus a second and third the operator had to invent.

- Added egg and pet distribution commands, closing a gap that made a Studio-created pet unreachable. Nothing minted eggs — the item codec could read and restore one but never sign a new one, and no command handed them out — so a saved definition had no route into a player's vault. `/pet admin egg give` now mints an egg carrying the canonical PDC identity, `/pet admin egg create` defines a catalog entry, and `/pet admin pet give` grants a pet directly for testing. Each egg occupies its own inventory slot because each carries its own nonce; stacking them would leave the escrow saga unable to tell which egg was paid for.
- Saving a pet in the Pet Studio now also writes `eggs/<definitionId>_egg.yml`, so a new pet is obtainable without hand-writing catalog YAML. An existing entry is never overwritten, since an operator may have tuned its duration or candidate pool. The write happens after the definition is saved, so a catalog failure cannot roll back or obscure the pet, and `gui.studio.autoCreateEgg: false` turns it off.
- The egg catalog repository gained a write path; it was previously read-only, which is why nothing could create an egg definition.
- Added audible and visual feedback for every state change. Activating a pet, claiming a hatch, buying a slot, a rejected purchase, and a blocked request are now distinguishable by sound instead of all being silent. Cues play to the acting player only — never to nearby players, which would make a spammable click a griefing vector — are rate-limited per player, and sit beside the existing chat message so text remains the accessible channel. `gui.feedback.enabled: false` turns everything off in one switch.
- Added an optional `gui:` section to `config.yml` owning feedback toggles and sounds, the vault page size, the help page length, and the Studio prompt timeout. Fourteen former Java literals now read from it. The section is lenient, following the `messages.yml` precedent rather than the strict `storage:` one: an unknown key warns, a bad value falls back per key, and an out-of-range page size clamps with a warning, because a typo in a display setting must never stop players using their pets. Deleting the section reproduces the previous behaviour exactly. **`gui.vault.petsPerPage` and `gui.studio.promptTimeoutSeconds` are restart-only and documented as such; `gui.feedback.*` and `gui.help.linesPerPage` reload live.**
- Added vault sort and filter. Five sort orders (favorites-first, level, rarity, name, recent) and four filters (all, favorites, active, stored) cycle on a click, in memory over the already-loaded snapshot with no extra repository read. Every comparator is total and ties on pet UUID, so no pet can appear on two pages or vanish. A vault with no pets, a filter matching nothing, and the last page now render three distinct messages where they previously looked identical or, for the last page, silently dropped the NEXT arrow.
- Added right-click pet interaction: right-clicking your own rendered pet opens its management screen. It consumes the activation index that already shipped, through a lookup that rejects stale renderer generations, and filters the off-hand event so one click opens exactly one screen. Another player's pet does nothing and a non-OmniPet entity is left uncancelled. Riding remains unimplemented.
- Added a unified player hub: `/pet` with no arguments now opens it, with Vault, Hatch, Active slots, Help, and (staff only) Studio tiles, each showing a live summary from one coalesced storage read. `/pet <page>` and the new `/pet vault [page]` keep direct vault access; vault, hatch, and management gained back-to-hub controls.
- Added `/pet help [page]` and permission-filtered tab-complete, both generated from one declarative command spec so they cannot drift from the dispatcher. Grouping literals such as `admin` only appear when the sender holds one of their child permissions.
- Added `messages.yml`: player-facing chat, GUI titles, and GUI lore are now operator-editable with MiniMessage, generated from the built-in defaults on first start, and reloaded by `/pet admin reload`. Unknown keys warn, missing keys fall back, broken tags render literally, and the file never disables the plugin. Operator audit output stays in the plugin.
- Added a shared `GuiItems` builder: no OmniPet menu renders italic lore any more, lore is grouped with a consistent colour grammar, and titles carry location context.
- Added Studio input fixes: every chat field now prompts with format, example, and the `cancel` hint; clicking a stat shows one explained button per supported modifier before asking for `min max` (the full `FLAT 10 50` form still works); the head-icon field auto-detects a pasted base64 payload, an `http(s)` URL, or a bare 64-character texture hash while keeping the legacy `<SOURCE> <value>` form.
- Added player schema 4 with a typed singular incubation state, deterministic `splitmix64-v1` hatch outcomes, bounded action-token idempotency, and capacity-safe atomic claim behavior.
- Added schema 1 egg-definition codecs/repository for one-file-per-egg catalogs with duration parsing, weighted candidates, case-safe IDs, and bounded file/catalog reads.
- Added the dependency-neutral item-escrow saga with atomic exactly-once create/compare-transition behavior, stable item identity, bounded journal reads/scans, and conservative recovery directives.
- Added the Paper paid-start saga, UUID-safe join recovery executor, stable cancellation tokens, and a shared-queue monotonic online checkpoint coordinator.
- Added player-facing `/pet hatch` commands and a durable hatch GUI with exact main/off-hand capture, countdown refresh, escrow-committed gating, and capacity-safe READY claim presentation.
- Added the in-repo `HatchEvent`/`HatchEventListener` seam for successful persisted core state changes. Events carry `DeliveryStage.STATE_PERSISTED`; unchanged mutations emit no notification, observer failures are isolated, and a `STARTED` notification is not egg escrow/payment proof.

### Added

- Added **ModelEngine animation**: a pet's model now plays an idle, walk, or run clip chosen from how it is actually moving, with clip names overridable per definition under `behavior.animations`. Gait comes from the movement the steering controller already computes, so no renderer port method was added — a dash counts as running even below top speed, because that is the controller deciding to catch up and the animation should agree. A clip is switched only on a gait change; re-issuing the playing clip every tick would restart it and a walking pet would never leave its first frame. `RendererCapabilities` gained an `animation` flag reported **per renderer instance**, since whether clips can be driven depends on the server's ModelEngine build rather than on the implementation.

  The animation methods are bound **separately** from the ones the renderer cannot work without, and are allowed to fail. The core bindings are resolved eagerly and a failure there quarantines the whole renderer, which is correct for `createModeledEntity` — there is nothing to show without it — but applying that to animation would mean a build that renamed one animation method took every pet's model with it. A missing animation API, or a definition naming a clip the model does not contain, now costs clips and nothing else; it is reported once per provider instance rather than once per tick. A source-level test pins the separation, because no runtime test can reach it without the vendor plugin on the classpath.

### Added

- Added a **first-join greeting**: two lines telling a brand-new player the pet system exists and that `/pet` opens it. Nothing did this before — all three join handlers recovered durable state, and discovery relied on a player already suspecting there was something to type, since `/pet` tab-completes only for someone reaching for it. Sent once, never to a returning player, and switchable off with `gui.onboarding.firstJoinGreeting` for a server that runs its own introduction.

### Changed

- **The action bar now works.** The channel was fully built — output, config switch, per-event key — but no `FeedbackEvent` ever supplied a key, so `gui.feedback.actionBar: true` was advertising a feature that did nothing. Summoning, recalling, starting an incubation, claiming a hatch, and unlocking a slot now confirm on the action bar as well as by sound. Repeatable actions such as cycling the vault sort stay sound-only: narrating those would make the channel noise rather than confirmation.
- **Placing an egg is discoverable.** The mechanic shipped and worked, but appeared in no documentation and the egg's own lore advertised only `/pet hatch main`, so it was reachable essentially by accident. The lore now mentions it and `docs/getting-started.md` explains the heat requirement, the pause-on-removal behaviour, and why breaking a placed egg cannot duplicate it.
- **Management failures read as sentences instead of enum names.** When an outcome carried no detail of its own, the status reached the player as its lowercased constant — "persisted consumption pending" told them nothing, leaked internal vocabulary, and could not be translated because it was generated from the name rather than read from the catalog.
- **Corrected `docs/commands-and-permissions.md`,** which listed the player hub and right-click entity interaction under "Not implemented" while both shipped and were described as working elsewhere in the same file.

- **Wrote down the menu design language** as `docs/design-guidelines.md`. The conventions — colour as a semantic role, values-then-blank-line-then-hint lore, the `OmniPet ▸ Screen` title grammar, action and item bound in one call — were already followed by most screens but recorded nowhere, so a new contributor had to infer them from whichever renderer they opened first.
- **De-duplicated the menu layout logic.** Slot and material resolution existed twice, in `MenuLayout` and in a private copy inside the pet management renderer. Both refused a collision and both fell back to the built-in slot, but only by coincidence — nothing kept them in step, and a rule fixed in one would have stayed broken in the other. Both now go through `MenuButtonStyle`.
- **De-duplicated pagination.** The same `(size + 44) / 45` rounding and stale-page clamp were written out separately in two Studio screens. Both now use `MenuPage`, which is tested for the cases a hand-written copy gets wrong: rounding at an exact multiple of the page size, and a page index left over from before the list shrank. The cursor-paged admin list deliberately does not use it — an opaque continuation cursor has no page count, so showing "page 2 of 5" would be a lie.
- **Separated "you cannot click this" from "this cannot be undone" in the colour vocabulary.** The release button used `BLOCKED` when the pet was *unlocked* and a section-heading grey when it was locked, inverting both roles' documented meaning. Red was right for releasing a pet; the role name was not. `GuiColors` gained `DESTRUCTIVE` and `DISABLED`, so a renderer naming the wrong one is now wrong in the source rather than only in intent.
- **The six Pet Studio screens now use the same titles and message catalog as every other menu.** They were built from raw Java strings in an `OmniPet Studio | Screen` shape, so they neither matched the `OmniPet ▸ Screen` grammar nor could be translated at all through `messages.yml`.
- **Documented the menus an operator could already restyle but could not discover.** `adminTransactions` and `adminReconcile` were accepted by the config codec while appearing in no documentation, and the hatch menu's button list omitted `redeemMain`/`redeemOff`.

- **A pet now faces the way it is travelling.** It previously copied its owner's yaw and pitch verbatim, so it always looked where the player looked and never where it was going: orbiting pets slid sideways, and a pet catching up drifted backwards. The steering controller already computed the velocity every tick and the renderer boundary threw it away. Facing is now derived from that velocity, held rather than recomputed below a speed threshold so a hovering pet does not jitter, and rate-limited so a target crossing behind the pet reads as a turn instead of a snap. Pitch stays level — a pet that pitched with its owner would tip over whenever the player glanced at the sky.
- **A pet leans into a run.** Speed tips the display back, up to `render.maximumLeanDegrees` (0 keeps it upright). Applied to the display rather than the carrier, so it is purely visual: the clickable hitbox and the movement policy's distance checks still work against an upright position.
- **Fixed the display transformation being rewritten every tick for every pet.** An identical transformation still restarts interpolation and dirties the entity's data watcher, so a stationary pet cost a packet per tick for nothing, multiplied by every pet on the server. It is now written only when the scale, gait, or lean would actually differ.
- **Added a `render:` config section**, so renderer movement is tunable at all. `PaperHeadRendererSettings` was never wired to config — both renderers built their own from hardcoded defaults — and the ModelEngine adapter carried a *second* copy of the gain, velocity ceiling, and safety distance, so retuning one renderer silently left the other alone. Both now share one section. Strict like `runtime:` rather than lenient like the display settings: these values steer entities, so a misspelled key is refused rather than ignored, and an absent section is the built-in tuning.
- **Documented the per-pet `behavior:` block** in `docs/configuration.md`. Sixteen movement knobs — pattern, follow distance, orbit, bob, spring, damping, dash, snap distance — were readable by the runtime but appeared in no documentation, and the same file wrongly claimed nothing consumed the block. The Studio's own example advertised `glow=true;particle=flame`, neither of which exists as a key, so an operator who followed the prompt got a pet that moved exactly as before; it now names keys the runtime actually reads.

- Removed the pre-rewrite `src/` tree at the repository root: 84 Java files and 5,262 lines that Git tracked but Gradle never compiled, because `settings.gradle.kts` only includes `omnipet-core` and `omnipet-paper`. It could not have been the gameplay authority its own documentation implied, and it made every repository-wide search return two answers for the same symbol. Git history remains the record; `docs/developer-guide.md` and `docs/examples.md` were corrected to stop describing it as live migration reference.
- Grouped the placed-egg wiring into `PlacedEggServices`, following the existing `*Services.open(...)` precedent. The store, coordinator, view, and block listener are only correct together — two coordinators would each hold their own store and could disagree about whether a block still carries an egg — so assembling them in one place makes that invariant local instead of spread through plugin startup. What happens when a countdown finishes stays with the caller, since hatching needs the pet registry and the owner's resolved storage limits.

- **Fixed** the reconcile menu being unable to act on any transaction past the first page, while telling the operator the opposite. The confirm screen re-reads its row before acting — deliberately, so a transaction another operator already resolved cannot be decided from a stale menu — but the re-read scanned from the start of the journal instead of from the page the row was shown on. Past 50 journal entries the row was never found, so the operator was told it "was already reconciled" and bounced to page one, when in fact it was still pending and now unreachable from the menu at all. The re-read now carries the page cursor, and a missing row reopens the page it came from rather than the first.
- **Fixed** the reconcile menu reopening its list before the decision it was meant to show had been applied. The journal write runs asynchronously and the reopen was scheduled alongside it rather than after it, so the reopen won the race and redrew the row the operator had just decided — reading as the decision having been lost. Money was never at risk: the reconciliation service locks per transaction and rejects any state not awaiting review, so a re-click returned an invalid-transaction result. The reopen is now chained onto the write completing.
- **Fixed** two config round-trip tests failing on any Windows checkout while passing in CI. Both inject test config by anchoring a `replace` on `"...\n"`, but `config.yml` is CRLF on a default Windows clone, so the anchor never matched, the injection silently became a no-op, and the assertion compared against a value that was never inserted. The loader was never at fault. The fixtures now normalise line endings, and `*.yml`/`*.yaml` are pinned to LF in `.gitattributes` so a parsed resource cannot differ by platform again.
- **Fixed** a failed pending-transaction read leaving the operator with no indication of what went wrong. `GUI_ADMIN_TX_LOAD_FAILED` was declared but never wired, so a journal read that threw produced only the generic operation-failed line and no menu — with nothing to say the list itself was what could not be read. Both menu entry points now report it.
- **Fixed** shrinking `gui.menus.adminTransactions.size` silently dropping transaction rows behind up to eighteen near-identical warnings. Rows were laid out against the built-in 54-slot shape regardless of the configured size, so each row past the smaller menu warned that its slot was out of range and fell back to the same out-of-range slot. Rows are now bounded by the menu's actual size, the count tile reports what is actually shown, and one warning names how many were deferred and where to find them.
- **Fixed** the hatch redeem controls repeating the start buttons' slot literals instead of deriving from them, so relocating `startMain` in config left the two sets describing different slots. They never collided at runtime — the start and redeem controls render in mutually exclusive branches.
- **Fixed** a Studio-created pet still being unobtainable in the common case. A new Studio draft starts with no rarity bands and a save accepts that, but the incubation reader treated a missing `rarity` node as fatal. The egg minted for such a pet was delivered and accepted, then the roll threw deep inside hatch start — so the player was told the hatch was queued and nothing ever happened, with only a server-log line to show for it. A definition with no authored rarity now hatches against a single implicit full-range band. An explicit but malformed `rarity` node is still rejected; only genuine absence defaults. The previous test asserted the egg *file's* contents and never drove the egg back through hatch start, which is exactly where the mismatch lived.
- **Fixed** `/pet admin pet give` doing repository I/O on the main thread. It read and wrote player state directly through the file repository, which takes a lock and fsyncs, so granting a pet to someone with a vault toggle in flight parked the server for every online player. The grant now runs on that player's task queue like every other admin mutation, with only the Bukkit lookup and messaging on the main thread.
- **Fixed** a lost revision race in the same command escaping as an internal error. Reading the revision and admitting under it are separate lock acquisitions, and `StaleRevisionException` extends `IllegalStateException`, so it slipped past an `IOException | IllegalArgumentException` handler and unwound into the command dispatcher — a retryable conflict presented as a plugin crash. The grant now retries on a fresh revision and reports the conflict plainly if it still cannot win.
- **Fixed** an admin-granted pet being scored as the weakest rarity. The grant wrote the pet's tier letter into `rarityId`, which holds a rarity *band* ID from a roll that never ran. Readers matched nothing and fell back to the lowest rarity, so an S-tier granted pet levelled at common-pet cost and vault rarity sort interleaved tier letters with band names nonsensically. The field is now omitted, which both readers already handle; `source: admin-grant` still records the provenance.
- **Fixed** a legacy config migration resetting a tuned EXP curve to the default. `encode()` wrote `progression.defaultExperienceFormula` as a hardcoded literal, because compiling a formula is one-way and only the compiled lambda was retained. The source text is now carried beside it. Latent rather than live — the migration path is the only caller and such a file has no `progression` section — but it was a trap for the next caller.
- **Fixed** `gui.help.linesPerPage` being documented as restart-only in `config.yml` and twice in the docs. Help paging reads the setting per command and the GUI settings are rebound on reload, so it has always applied live. The comment was corrected rather than the code.
- Removed the write-only `integrations` config section. It was allowed as a root key, never read, and rewritten from hardcoded strings that decode ignored. The section is still accepted so an existing file keeps loading, but it is no longer written; the reference vendor builds moved to [integrations](docs/integrations.md), and `paper-plugin.yml` already owns the real dependency contract.
- Restructured `config.yml` around what an operator is deciding rather than which loader parses it, and stated the strict/lenient split up front so the consequence of a typo is predictable per section.

- **Fixed** a startup crash on Paper 1.21.11. `org.bukkit.Sound` is an enum on Paper 1.21 and 1.21.1 but an interface from 1.21.11 onward, so the feedback layer's `Sound.valueOf(name)` compiled to a `Methodref` against the enum and threw `IncompatibleClassChangeError` at class-load time — the plugin failed to enable at all rather than merely losing its sounds. Sound names now resolve through `Registry.SOUNDS`, whose signature is identical on every probed line. A contract test walks the constant pool of every compiled class and fails on any non-interface reference to `org.bukkit.Sound`, so a compile probe passing is no longer mistaken for the call being safe.
- **Fixed** a main-thread stall in vault sorting found during verification. The comparators re-derived each pet's summary on every comparison rather than once per pet, which at the 100,000-pet vault capacity was a 1.4-second freeze — roughly 28 ticks — from one sort click. Sort keys now derive once; the same case drops to about 250ms and a realistic 1,000-pet vault to under 5ms, with ordering unchanged.
- **Fixed** the hub slot tile returning to the wrong screen. A slot purchase opened from the hub replayed `pet <returnPage>` on cancel, on success, and on a stale quote, silently relocating the player to vault page 1 instead of back to the hub. The return command now belongs to an explicit origin carried on the purchase holder, so all three return points agree.
- The hub gained the concurrent-open guard its four sibling controllers already had, released on every failure path so a failed open cannot lock it.
- Collapsed duplicated formatters into `text/Durations`: the countdown existed twice (hatch menu and hub tile) and the decimal formatter twice (management screen and Studio stat screens). Output is unchanged and pinned by a test written against the pre-migration behaviour. Seven copies of enum-to-text conversion — two more than an earlier audit found — now route through `Displays`; operator and audit strings keep their raw enum form.
- `/pet` with no arguments now opens the player hub instead of vault page 1. `/pet <page>` and `/pet vault [page]` preserve direct vault access.
- Rebranded the public project, descriptor, examples, and operator documentation as OmniPet by SalyVn.
- Switched the documented build workflow from Maven to Gradle Kotlin DSL.
- Added Paper 1.21.x/Java 21 and Paper 26.1+/Java 25 compatibility guidance with an explicit alpha/experimental caveat for 26.x.
- Added a static GitHub Pages workflow that publishes `docs/` without repository secrets.
- Added migration guidance for legacy `passivepet` permissions, PDC keys, MMOItems stat IDs, data folders, and stable YAML fields.
- Added dual-read documentation for legacy item identifiers and optional MythicLib/MMOItems integrations.
- Unified vault and slot-purchase work behind one plugin-owned per-player queue, with namespaced pending-read coalescing and FIFO cross-controller serialization; hardened lifecycle shutdown ordering, accepted-mutation draining, and dispatch-rejection isolation.
- Hardened hatch timing and recovery: the monotonic baseline begins only when committed escrow is observed, failed persisted ticks accumulate elapsed online time, and start-failure/tick/join recovery uses bounded pending scans with explicit operator-review warnings.
- Updated clean-build evidence to the current JDK 21 Gradle verification checkpoint: 18/18 tasks, 147 suites/605 tests (core 63/256, Paper 84/349), zero failures/errors/skips, a 1,674,717-byte artifact, and zero Maven or bundled MiniMessage entries. Compatibility probes, crash-injection proof, and live-server certification were not rerun for this checkpoint.

### Compatibility notes

- Paper 1.21.x is the primary release line.
- Paper 26.1.1 artifacts observed during research were alpha builds; no blanket `26.1.1+` support claim is made.
- Paper 26.1+ requires Java 25. MythicLib, MMOItems, MythicMobs, and ModelEngine vendor support must be verified separately.
- ModelEngine and Paper display-entity rendering remain roadmap adapter boundaries; no live renderer is shipped in this checkpoint.
- Paper incubation now includes the paid-start saga, monotonic online checkpoints, conservative join recovery, hatch commands, and escrow-gated GUI claim presentation. Crash-injection proof and live-server certification remain deferred.
- Reducer/instant-hatch items, native item distribution, hard MMOItems integration, and a separately versioned public addon API remain deferred. Any consumable hatch item must add durable redemption/escrow; an action token or core state notification alone is insufficient settlement proof.

### Migration notes

- Keep `globalMaxSlots`, `slotPermission`, `duration`, `rarity`, `pets`, and component IDs unchanged when migrating existing YAML.
- Existing `passivepet:*` item PDC keys and `PASSIVEPET_*` MMOItems stat IDs are treated as legacy compatibility identifiers. New items use OmniPet identifiers.
- Back up `plugins/PassivePet/` and `plugins/OmniPet/` before switching descriptors or copying data. Resolve conflicts manually; never merge two live player-data directories blindly.
- Player schemas 1-3 migrate to schema 4 while preserving raw `currentEgg` and pre-v4 top-level `incubation` data. Root `eggs.yml` stays migration input; canonical core definitions use `plugins/OmniPet/eggs/*.yml`.
